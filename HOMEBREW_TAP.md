# Homebrew Tap for hookset

## What is this?

A Homebrew tap is a GitHub repository that holds Homebrew package definitions. When you install a formula from a tap, Homebrew fetches the formula and downloads the specified binary or builds from source.

**Install hookset with:**

```bash
brew install bulga138/homebrew-hookset/hookset
```

Or add the tap first:

```bash
brew tap bulga138/homebrew-hookset
brew install hookset
```

## How it works

This tap is **auto-generated by goreleaser** on each release. The formula contains:

- Version number (from the GitHub release tag)
- SHA256 checksum (calculated from the release binary)
- Download URL (points to the GitHub release assets)

When you run `brew upgrade hookset`, Homebrew automatically downloads the latest release.

## For maintainers

### Setup (one-time)

1. Create this repository: `bulga138/homebrew-hookset`
2. Add the repository name to `.goreleaser.yml`:

```yaml
brews:
  - name: hookset
    repository:
      owner: bulga138
      name: homebrew-hookset
```

3. Create an initial `README.md` in the tap repo (goreleaser will update the formula, not this file).

### Release workflow

On each git tag, goreleaser:

1. Builds binaries for all platforms
2. Uploads to GitHub Releases
3. Generates and pushes the formula to this repository

No manual steps needed after the initial setup.

### Formula structure

The generated formula looks like:

```ruby
class Hookset < Formula
  desc "Git 2.54 config-native hook manager"
  homepage "https://bulga138.github.io/hookset"
  url "https://github.com/bulga138/hookset/releases/download/v1.0.0/hookset_1.0.0_darwin_arm64.tar.gz"
  version "1.0.0"
  sha256 "abc123..."
  license "MIT"

  def install
    bin.install "hookset"
  end

  test do
    system "#{bin}/hookset", "version"
  end
end
```

## Verification

Check the formula is valid:

```bash
brew audit --tap bulga138/homebrew-hookset/hookset
```

## Uninstall

```bash
brew uninstall hookset
brew untap bulga138/homebrew-hookset
```

# Goreleaser Configuration

Goreleaser automates releases for Go projects. Here's how to configure it beyond the `.goreleaser.yml` file.

## Prerequisites

```bash
# Install goreleaser
brew install goreleaser

# Or via Go
go install github.com/goreleaser/goreleaser@latest
```

## GitHub Token Setup

Goreleaser needs a GitHub token to upload releases:

1. Create a Personal Access Token at https://github.com/settings/tokens
2. Required scopes: `repo` (for releasing), `workflow` (for CI)
3. Set it as an environment variable:

```bash
export GITHUB_TOKEN="ghp_xxxxxxxxxxxx"
```

Or in GitHub Actions:

```yaml
- name: Run Goreleaser
  uses: goreleaser/goreleaser-action@v5
  with:
    version: latest
    args: release --clean
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Local Testing

Test your configuration without releasing:

```bash
# Dry run (creates files in ./dist but doesn't upload)
goreleaser release --clean --skip-publish

# Or just build
goreleaser build
```

## Version Management

Goreleaser uses git tags for versioning:

```bash
# Create a release
git tag v1.0.0
git push origin v1.0.0

# Check current version
goreleaser release --clean --skip-publish --skip-sign --snapshot
```

For automatic version bumps, use [git-chglog](https://github.com/git-chglog/git-chglog) or similar.

## CI/CD Integration

### GitHub Actions

Add to your release workflow (see `.github/workflows/release.yml`):

```yaml
name: Release
on:
  push:
    tags:
      - 'v*'

jobs:
  goreleaser:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Set up Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.24'

      - name: Run Goreleaser
        uses: goreleaser/goreleaser-action@v5
        with:
          version: latest
          args: release --clean
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Configuration Options

### Binary Name Override

```yaml
builds:
  - binary: hookset
    # instead of default (project name)
```

### Custom Build Tags

```yaml
builds:
  - id: hookset
    go_ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
```

### Multiple Binaries

```yaml
builds:
  - id: hookset
    main: ./cmd/hookset
  - id: helper-tool
    main: ./cmd/helper
```

### Custom Install Script

```yaml
brews:
  - name: hookset
    install: |
      bin.install "hookset"
      man1.install "hookset.1"
```

## Common Commands

| Command                         | Description                      |
| ------------------------------- | -------------------------------- |
| `goreleaser init`               | Create initial `.goreleaser.yml` |
| `goreleaser check`              | Validate configuration           |
| `goreleaser build`              | Build locally (no release)       |
| `goreleaser release --clean`    | Full release cycle               |
| `goreleaser release --snapshot` | Snapshot release for testing     |
| `goreleaser purge`              | Clean up dist directory          |

## Troubleshooting

### "latest tag is not present"

```bash
git fetch --tags origin
```

### "tag v1.0.0 is not a valid semver"

Tags must be valid semver: `v1.0.0`, not `1.0.0`

### "no previous tag found"

For first release, create an initial tag:

```bash
git tag v0.0.0
git push origin v0.0.0
```

### Upload fails

Check your GitHub token permissions and token expiration.
